# Resonance 共鸣（选图）

目标：让用户**看着图**选方向。用户往往说不清想要什么，但一眼就知道喜欢哪张。
能摆图就不要提问，能给两张图对比就不要用文字解释区别。

## 开始之前

1. **图给谁看**：期刊正文 / 补充材料 / 组会 / 海报——受众不同，合适的图不同。用户说了就不必再问。
2. **数据长什么样**：自己打开数据看列数、行数、分组、范围。只有会改变图含义的歧义才问用户。

## 找图

1. **先跑场景路由器**（把用户的话翻译成跨家族候选，防止单家族垄断）。
   在技能目录运行；不在技能目录时用绝对路径（下同，`<SKILL>` 指技能根目录）：

```bash
python scripts/route.py "<用户的原话或转写的意图>" --n 9 --log
# 有数据文件时加 --data data.csv: 自动做契约校验, 缺列的候选降权并注明缺口
# 用户要"高级/惊艳"直接加 --min-wow 2
```

   路由器综合五层：语义打分（逐图的场景档案 reference/routing/segNNN.json）→ 气质调权 →
   数据适配 → 近期展示去重（route_log.jsonl）→ **多样性硬约束（top-N 内每家族 ≤2）**。
   输出 A/B/C 菜单与现成的样板册命令。
2. **打开候选图确认**：路由结果只是线索，合不合适要看图。直接用路由器给的样板册命令，
   或手工指定候选：

```bash
python scripts/make_contact_sheet.py sheet --out /tmp/candidates.png "5::我的推荐" "69::贴近你的口味" "121"
# 路由器不可用/档案缺失时的备用路径: grep gallery/index.md 用途词 + --family 取样
```

3. 候选不对路就扩大范围：换意图措辞重跑路由 → 相邻家族 → 参考 `gallery/cards/` 的 data 字段确认数据形状撑不撑得起。
   图库确实缺这一类时如实说，并可以给一个图库之外的方案画成草图，标明"不在图库中"。

## 高级感通道（用户说"要高级/惊艳/顶刊范"时）

不要反问"多高级"——直接摆 wow 样板册让用户看：

1. 跨家族起手：`python scripts/make_contact_sheet.py sheet --out /tmp/wow.png --min-wow 3 --sample 9`，
   文字菜单注明每张的惊艳点（取卡片"高级感"行）。
2. 结合数据情形收窄：从 `reference/selection.md` 第 0 节按惊艳点找 wow=3 候选，
   留数据撑得起的 2-3 张，用真实数据画草图终选（按 3-rendition）。
3. **wow 是惊艳度，不是合适度**：数据撑不起复杂结构（三元和不为 100%、桑基层级缺失、
   环形图类别太少）就退一档，向用户说明原因。朴素而正确的图好过惊艳而错误的图；
   用户坚持要惊艳时，把数据缺口和取舍讲清楚再画。

## 澄清问题库（data-to-viz 式反问，仅在需要时问）

路由结果的 top 候选**跨家族分裂**（前 3 名属于 ≥2 个 family 且分数接近）时，从下面 5 问里挑
最关键的一问问用户（一次只问一个），其余时候自己看数据判断，不拿数据问题轰炸用户：

1. 每组是单个观测还是多个重复观测？（决定能不能画分布/误差棒）
2. 数值加起来是不是 100%/占比？（决定构成类选哪张）
3. x 轴是有序量还是类别？（决定折线还是柱形/分组）
4. 你要看总量还是占比随时间的变化？（堆积柱两种画法）
5. 数据有层级吗（大类套小类）？（决定桑基/环形/普通分组）

## 摆样板册

- 每轮 6–9 张，自动标 A、B、C…；第一轮要拉开差距（从朴素到华丽），让用户先定大方向。
- **TUI 呈图**：生成后加 `--open` 用系统看图器打开（无人值守会话用 `scripts/show.py --print-only` 只留路径）；
  同时在对话里给**文字菜单**——每个候选一行 `A. seg005 云雨图 —— 有什么用（取卡片"有什么用"，直白话）
  + 为什么推荐给你（结合用户数据一句话）`，用户看图选字母、看文字也选得出。用户看不到图时
  （无 GUI/纯文本会话），改给文字菜单 + 参考图路径。
- 每轮都摆两类并标注：**「我的推荐」**（面向受众与数据最合适，附一句理由）与**「贴近你的口味」**
  （依据 `taste.md` 与本次对话里的偏好）。只迎合口味是偷懒，最终选择权在用户。
- 卡片里有注意点的照常摆出，附上那句注意点。
- 告诉用户可以怎么回答：选一张，或组合，例如"B 的布局 + F 的配色"。

## 快速路径："你定"

自己完成筛选，首选方案直接画成成品交付，附另外两个方向的缩略图和一句推荐理由。

## example 入口：用户给了例图

1. 看懂例图的用途、数据形状、六个部件（结构布局 / 图形元素 / 配色 / 文字标注 / 装饰 / 图例色条）。
2. 摆一张对照样板册：用户例图（如有数据可画）+ 图库里最接近的案例 + 两三张同用途但气质不同的图。
3. 图库里有同款时直接指出案例号；用户的数据撑不起例图结构时，说明缺什么，给出最接近的候选。

## 收窄与定稿

- 用 1–2 轮把方向收到 2–3 个，每轮比上轮更接近。
- **最后一轮用用户真实数据画草图**（按 3-rendition，草图不必精修）拼样板册让用户终选。
- 用户已明确选择时直接进 Rendition，并把"从哪张图取哪个部件"整理成清单带走。

## 品味记录

`taste.md` 每次用户做出选择或否决后追加一行，只用于摆"贴近你的口味"，不用于排除任何图：

```
2026-10-07 | 期刊正文 | 选了 seg005 的布局 + seg041 的配色 | 否决 3D 饼图 | 想要"安静不花哨"
```

`taste.md` 为空（首次使用）时，样板册省略"贴近你的口味"一栏，全部摆"我的推荐"，不必追问用户口味。
